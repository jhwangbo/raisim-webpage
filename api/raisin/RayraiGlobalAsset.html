raisin::RayraiGlobalAsset ​

class · #include <rayrai/RayraiGlobalAsset.hpp>

A caching asset manager for 3D models and primitive meshes.

This class loads models on demand and keeps them in memory as long as they are being used. Once all references to a model are released, its memory can be reclaimed. It also owns reusable meshes for primitives such as cubes, spheres, cylinders, and capsules.

Returned mesh lists are shared: every caller that requests the same asset gets the same std::shared_ptr, so mutating a mesh's material affects all users. Not thread-safe; use it from the thread that owns the GL context.

Nested classes ​

  • struct MeshLodChain — Internal: cached automatic-LOD chain shared by Visuals of the same source mesh.
  • struct SharedGpuAssetStats — Counters of the process-wide shared GPU-asset cache (see sharedGpuAssetStats()).

getMeshes ​

cpp
std::shared_ptr<std::vector<std::shared_ptr<OpenGLMesh>>> getMeshes(const std::string &name)

Retrieves a model's meshes by its asset name (usually file path).

Assets are keyed by canonical path, so different spellings of the same file share one mesh list. With async loading enabled (the default; USD files always load synchronously) a new file returns an empty list at once that is filled in place by a later pollAsyncLoads(); if that import fails the list stays empty. The cache holds only weak references. Requires a current GL context for synchronous loads.

Parameters

ParameterDescription
nameThe unique identifier for the asset, typically the file path.

Returns Shared mesh list (possibly still empty while loading), or nullptr if the path does not exist or a synchronous load fails.

pollAsyncLoads ​

cpp
size_t pollAsyncLoads(size_t maxAssets=1)

Advance ready import, worker geometry, and incremental GPU upload stages.

This must be called on the OpenGL/render thread because it creates textures, vertex buffers, and vertex array objects. Each processed asset advances one stage (import, geometry preparation, or one submesh upload) per call. Throws std::logic_error as requireUploadContext() does, before advancing any.

Parameters

ParameterDescription
maxAssetsMaximum number of pending assets advanced in this call.

Returns Number of assets finalized (successfully or not) in this call.

pollAsyncLoadsUntil ​

cpp
size_t pollAsyncLoadsUntil(std::chrono::steady_clock::time_point deadline)

Advance every pending import as far as it can go before deadline.

Like pollAsyncLoads(), on the OpenGL/render thread, but an asset keeps advancing (one submesh upload after another) until it waits for a worker or the deadline passes. Imports whose worker finished go first, so the next worker stages start early. With async loading enabled, an import is finished only once the background decodes of its textures are done, so the render thread decodes no image. At least one ready stage runs per call. Throws std::logic_error as requireUploadContext() does, before advancing any.

Parameters

ParameterDescription
deadlineTime after which no further stage starts.

Returns Number of assets finalized (successfully or not) in this call.

requireUploadContext ​

cpp
void requireUploadContext()

Fails unless the OpenGL context current at construction is current.

The store's textures, vertex arrays and staging regions belong to that context, so its loads advance only there. Elsewhere every pending load first gives its staged copies back to the staging buffer (it stages again, or uploads directly, once polled in its context), and then this throws std::logic_error.

setAsyncMeshLoadingEnabled ​

cpp
void setAsyncMeshLoadingEnabled(bool enabled)

Enable or disable async mesh file import for future getMeshes() calls.

Loads already pending keep loading asynchronously (they wait for the background decodes of their textures and copy through the staging buffer), unless a synchronous getMeshes() waits for one of them or loadPendingSynchronously() is called.

Parameters

ParameterDescription
enabledTrue (default) to import on a worker thread; finalize with pollAsyncLoads().

loadPendingSynchronously ​

cpp
void loadPendingSynchronously()

Makes every pending load finish synchronously as it is polled: it no longer waits for the background decodes of its textures or for room in the staging buffer.

RayraiWindow::setAsyncMeshLoadingEnabled(false) calls this before finishing them.

forgetChangedModelFiles ​

cpp
void forgetChangedModelFiles()

Forget every cached model file whose sources changed since it was read.

A model's sources are its file and every file its import read (glTF buffers, an OBJ material library, ...). A changed one makes the next getMeshes() read the model again, even while visuals still hold the meshes read before. RayraiWindow::swapWorld() calls this, so a rebuilt scene shows edited files.

releaseRecentlyReadModels ​

cpp
void releaseRecentlyReadModels()

Release the models read from files since the last call.

A model read from a file stays referenced until this is called, so every visual created in the same frame shares one read, even when a visual keeps only meshes derived from it (instanced foliage keeps its partitioned meshes, and a terrain foliage layer adds one visual per chunk). RayraiWindow calls this at the end of each update(), renderWithExternalCamera(), and depth-only render.

static void configureDefaultPrimitivePbrMaterial(
    const std::shared_ptr<std::vector<std::shared_ptr<OpenGLMesh>>> &meshes,

Configure the default material used by built-in primitive meshes.

The material remains a PBR material, but enabled controls whether it is allowed to enter the PBR pass or forced through the cheaper simple shader. Overwrites the base color, metallic, roughness and IBL strengths of every mesh in meshes.

Parameters

ParameterDescription

enabledFalse sets Material::forceSimpleShading.
