raisin::InstancedVisuals ​

class · #include <rayrai/Visuals.hpp>

Many copies of one shape or mesh drawn with GPU instancing.

Each instance has a position, wxyz orientation, scale and a color weight that blends between the two batch colors (getColor1(), getColor2()) (mix(color1, color2, weight)). Appearance (colors, category, shadow flag) is shared by the whole batch. Instance edits are cheap CPU updates; the GPU instance buffer is refreshed lazily on the next draw, which requires a current GL context. Mesh batches may get automatic LODs prepared on a worker thread; such a batch draws nothing until that preparation has finished (see pollAsyncMeshPreparation()). Batches that look like foliage (alpha-masked or foliage materials, or a foliage-like file name) also enable shadow LOD, cluster culling and impostors by default.

setCategory ​

cpp
void setCategory(VisualCategory category)

Set the render category used by capture/detection filters.

The category is shared by all instances in this batch. It controls whether the instanced visual is included when a rayrai pass excludes non-detectable visualization objects, such as external camera scene-color renders, capture paths that reuse external-camera rendering, or picking/shadow candidate policies that request detectable custom visuals. The normal interactive viewer includes both categories by default.

This is render metadata only; it does not create collision, physics behavior, or per-instance semantic labels. New InstancedVisuals default to VisualCategory::NotDetectable.

Parameters

ParameterDescription
categoryNew render category for the whole instanced batch.

See also VisualCategory

pollAsyncMeshPreparation ​

cpp
bool pollAsyncMeshPreparation()

Finish worker-prepared LODs incrementally on the render thread. Starts the worker on the first call and uploads one prepared submesh per later call; draws also call it. Requires the batch's GL context: once its uploads began in one context, a call with another current gives the staged uploads back (see releaseStagedAsyncMeshUploads()) and throws std::logic_error; a draw there leaves the batch pending instead.
